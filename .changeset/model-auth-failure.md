**A rejected model API key is reported as a key problem.** When the provider answered 401 or 403 (an expired, revoked or wrong key), `record` filed it as an `authoring` failure. Its hint asked for the step to be reworded, and before giving up it spent a repair attempt and a fresh retry, each hitting the same refusal. Neither could ever succeed. A refused key is now its own failure kind, `model_auth`. The message names the provider ("Anthropic refused the API key (http status 401)") and keeps the provider's explanation. The hint says to set a working key with `flowproof config ai`, and the recording stops after the first refused call with no repair or retry.
