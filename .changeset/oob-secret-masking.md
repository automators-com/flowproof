**A failed database or API check no longer prints the secret it compared.** The UI checks keep a `${VAR}` as a reference in their failure messages, but SQL and API checks resolve their values before the probe runs, and the probe quoted what it held: `expected first column 'hunter2'`, `response body does not contain '<token>'`, a header's expected value, a url in a transport error. That text reached the terminal, `result.json`, and anything that shows a run. Their failure reasons are now masked against the step's own references, while recording and on every replay, so the message shows `${VAR}` where the value was.
