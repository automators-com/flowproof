**The vision grounding benchmark stops scoring vision for refusing what it
should refuse, and asks for a Calculator key by what it shows.** A window's
system menu and its Minimize, Maximize and Close buttons were in the answer
key, so every window lost three or four controls to a refusal that is right -
a step never means the chrome, and OCR reads its glyphs as `0` and `X`. They
are left out now, by name and place, so File Explorer's tab buttons in the
title bar still count. And a memory or reciprocal key is asked for as an
author sees it - `M+`, `MS`, `1/x` - not as "Memory add", which no pixel
spells. A split button reported as two controls of one name - File
Explorer's breadcrumb `Home`, its icon and its text - is one control of
the key, as it is one word on screen. Pixels-only name accuracy on five desktop apps reads 33% (Calculator
73%); the rest is mostly icons, which a model reaches through their `icon:`
names in the scene, and which this score cannot ask for by name.
