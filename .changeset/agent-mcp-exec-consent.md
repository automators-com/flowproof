**Recording a flow no longer runs its `agent.command` or MCP server command without consent.** `record` spawns the program named by a spec's `agent.command` and by each stdio `mcp.*.command` — arbitrary executables the spec author chose — so recording a flow from a folder you didn't write ran that author's program. These now require the same consent as suite shell: `record` refuses them by default, naming the exact program, and runs them only with `--allow-exec` (or `FLOWPROOF_ALLOW_EXEC=1`). Replay is unaffected — it never spawns them. `agent.url` and HTTP MCP servers, which flowproof does not start, are unchanged.
