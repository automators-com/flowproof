**A terminal's status line no longer stops a vision recording as the previous step's failure.** A host screen can show a standing message for as long as its input is incomplete, such as `1/01 :Eingabe unvollständig`. The authoring model reported that line as a problem the previous step had left behind. Recording stopped at the next step, with advice to add a wait that could never help. On vision, a "previous step left a problem" report is now only believed when the screen bears it out. It is refused when the quoted words were already showing before the previous step ran, when the screen does not show them at all, or on a flow's first step, where nothing has run yet. The comparison tolerates how OCR misreads a terminal font: dropped umlauts, `0`/`O`, `1`/`l` and spacing. A refused report does not use up the retry the step may need, and the model is told up front that standing messages are not failures. Reports of text the previous step did bring still stop the recording. Their hint no longer calls them a loading race: it says the screen still shows a problem and to check that step first (#846).
